# MingoQuiz v1.1.0

Released as the tag `v1.1.0` (its date is the GitHub release's). It follows [v1.0.0](v1.0.0.md) and changes only the web app and the docs: no migrations, no changes to the deploy scripts, Nginx or the bank import.

## What's in it

- **Home leads with today's questions:** each area's state (time on the clock, clock running, done), how many are left, the streak and one button, on the green ground. Rank and level follow; practice, mock and live quizzes are one list below ([players' guide](../guides/players.md#joining)). Home now reads the daily status, which picks the day's questions if the nightly job hasn't yet, as opening Daily always did.
- **Mock quizzes grouped by year**, newest open; filtering by class or name opens every year that matches ([players' guide](../guides/players.md#mock-quizzes)).
- **Admin shows the first 20 members** until "Show all *n* members"; the search still covers everyone ([admins' guide](../guides/admins.md#members)).
- **Countdown:** screen readers read the time left with its label (an `aria-label` hid the value from some), and a new deadline shows at once.
- **Live quizzes:** your own table in the standings has a "Yours" badge instead of a gold side stripe.
- **No layout shift on load:** the footer starts below the fold, and Practice takes its wide column before the question arrives for ranks with learning aids.
- **Design docs:** `PRODUCT.md` and `DESIGN.md` at the root describe who the app is for and its visual system; app colours the ISC tokens lack (answer states, rank metals) are named in `global.css`, and `tokens.css` stays a verbatim copy of the website's.

## Known issues

Unchanged from [v1.0.0](v1.0.0.md#known-issues), plus:

- Admin still shifts on load (its folded panels move down when the member list arrives). Admins only.
- The end-to-end suite has a race: `review.spec.ts` briefly hides a question that another spec may be practising, which can fail that spec with "That question doesn't exist." Re-run the job; a fix is planned.

## After deploying

- **Staging, then prod:** `deploy/deploy.sh staging v1.1.0`, check it (sign in, answer a practice question, open the leaderboard), then `deploy/deploy.sh prod v1.1.0`. No other steps are expected; do any `deploy: to do:` line the script prints ([runbook 2](../runbook.md#2-deploy)).

## Database

No new migrations: still 0001 to 0024. Rolling back to `v1.0.0` needs nothing else.
