# MingoQuiz v2.0.0

Released as the tag `v2.0.0` (its date is the GitHub release's). It follows [v1.1.0](v1.1.0.md) and is the ranked-play integrity release ([ADR 0010](../adr/0010-fair-play-and-integrity.md)): it adds migrations 0025 to 0028 (expand only) and changes the API, the web app, the scheduler and the operator tools. It deploys **dark**: nothing changes for players until the single switch `IFS_RULES_1B_FROM` (planned for Monday 26 October 2026, Madrid) is set and reached. Only the fair-play text and the accuracy on the boards are live at deploy.

## What's in it

**Fair-play policy and notice**

- **The rule, per mode:** ranked play (every daily question and the first run of each mock quiz in a season) allows the rulebook, handbooks, a textbook, your own notes, a calculator or Python and a translation tool, and does not allow an AI that reads the question, help from another person, or looking up the answer. Practice is unrestricted and live quizzes follow the host's room rules. In English and Spanish on About, with the board caption ([players' guide](../guides/players.md#fair-play), [game rules 10](../game-rules.md#10-fair-play)).
- **The privacy notice** names the per-answer totals recorded from the rule date, the two-person pseudonymous review, 90 days' retention after the season, and that a person decides, never the app. Records: [ADR 0010](../adr/0010-fair-play-and-integrity.md), the [LIA](../privacy/lia-integrity.md) and the [DPIA screening](../privacy/dpia-screening-integrity.md).

**What changes at the switch, for players**

- **A daily question per player:** the question is drawn for you when you press Start, so teammates usually get different ones and there is nothing to relay ([players' guide](../guides/players.md#daily-questions), [game rules 5](../game-rules.md#5-the-daily-question)). A question drawn for someone's daily is withheld from other people's practice, mock summary, review and live picks until their day closes.
- **Results at Madrid midnight:** a daily answer is graded and stored when sent, but its right or wrong, XP and LP, the board and the rank card move only at the midnight that closes the day. The daily page says "Locked in" meanwhile and "Your latest results" afterwards.
- **Option shuffle:** the options of a daily are shown in a per-attempt order, steady across reloads and the review. Positional and ordered options keep the bank order, and a reviewer can pin a question to it ([reviewers' guide](../guides/reviewers.md#option-order)).
- **Ranked signals:** the page sends a few totals with ranked answers (time away, declared or not, pastes into typed answers, long copies of the question). A "Looking something up" button declares a lookup. Advisory only: XP, LP, streaks and rank never read them, and they reach people only through their own export and the reviewed report.
- **Accuracy on the boards:** accuracy with its interval and the number of answers beside LP. The ranking order is unchanged.

**For operators and reviewers**

- **Integrity report:** `ifs-tests integrity-report` is read-only forensics with pseudonyms, a two-person reveal (`integrity-reveal`), and the signals and canary evidence as context; run through `deploy/integrity-report.sh` ([integrity report guide](../guides/integrity-report.md), [runbook 5.7](../runbook.md#57-integrity-report)).
- **Shuffle report:** `ifs-tests shuffle-report` shows how the option shuffle treats the bank, with a go/no-go rule to apply before the date ([runbook 5.9](../runbook.md#59-option-order-report)).
- **Settle:** a 00:01 `settle` job and the `ifs-tests settle` command grant the closed days' results; the health check watches `dailies_settle_failed` ([runbook 5.3](../runbook.md#53-run-the-maintenance-by-hand), [maintenance calendar](../maintenance.md)).
- **Canary off by default:** the honest AI canary (`IFS_CANARY`) stays off until the recall pilot passes and About names it.

## Known issues

Unchanged from [v1.1.0](v1.1.0.md#known-issues), which keeps [v1.0.0's](v1.0.0.md#known-issues), plus:

- The end-to-end suite has no gated-day job in CI: the specs run with the switch off, so the per-player daily, the day close and the shuffle are covered by the unit and API tests and by the staging rehearsal below.
- The browser matrix for the signals hook (focus, paste and copy events) has not been run, and the recall pilot that calibrates the canary has not been done.
- The flaky `review.spec.ts` race of v1.1.0 is still open.
- A browser tab left open from before the switch that answers a daily may show an error for the missing result; the answer is recorded and a reload shows "Locked in".

## Before the switch

- **Staging first, with the switch set:** put `IFS_RULES_1B_FROM` (today's Madrid date) in staging's `.env`, deploy, and run the rehearsal in [runbook 5.8](../runbook.md#58-season-1b-switch-v200), including the day-close rehearsal across a Madrid midnight.
- **Prod deploys dark,** only after the Technical Directors have signed ADR 0010 and the board the DPIA, since the release carries the About notice (target 19 October, a week before the date), with the team announcement in Spanish and English. Deploy with `IFS_RULES_1B_FROM=2026-10-26` (the signed date) already in prod's `.env`, as [runbook 5.8](../runbook.md#58-season-1b-switch-v200) step 2 says: before that Madrid day nothing changes for players. Deploy at least a day before the date so open tabs have reloaded, and make sure About's `RULES_FROM` shows the same date.
- **Moving the date** later is a `.env` edit and a restart, made only at a Madrid midnight ([runbook 5.8](../runbook.md#58-season-1b-switch-v200), step 6).
- Run `shuffle-report` on the local mirror and apply its rule ([runbook 5.9](../runbook.md#59-option-order-report)).

## After deploying

- **Staging, then prod:** `deploy/deploy.sh staging v2.0.0`, check it (sign in, answer a practice question, open the leaderboard), then `deploy/deploy.sh prod v2.0.0`. Do any `deploy: to do:` line the script prints ([runbook 2](../runbook.md#2-deploy)).
- **`integrity.env`:** `/srv/quiz/<env>/integrity.env` (`chmod 600`) must hold the 21 `IFS_INTEGRITY_*` values before the first per-person run; `grep -c IFS_INTEGRITY_ /srv/quiz/<env>/integrity.env` should say 21 ([runbook 5.7](../runbook.md#57-integrity-report)).
- **Follow-the-leader on prod, before the switch:** while the daily is still shared, run `deploy/integrity-report.sh prod report --until <announcement date> --checks follow` and read it with the Technical Directors; the per-player daily ends that signal ([runbook 5.8](../runbook.md#58-season-1b-switch-v200), step 3).
- **Leave `IFS_CANARY` unset (off).**

## Database

Migrations 0025 to 0028, all expand only: nullable per-answer totals and reopening counts on attempts (0025), a partial index for the daily and `mock_sessions.skipped` (0026), `released_at`, `settled_at` and `reward` on attempts plus a pending index (0027), and `questions.keep_order` and `daily_questions.first_drawn_at` (0028). Rolling back to `v1.1.0` works without a downgrade, because the older release ignores the new columns. **Before the switch** it needs nothing else. **After the switch**, drain the pending results first: move `IFS_RULES_1B_FROM` later at a Madrid midnight, let a midnight pass, run `docker exec quiz-prod-scheduler-1 ifs-tests settle --drained` from the v2.0.0 image until it exits 0, and only then deploy the previous tag ([runbook 5.8](../runbook.md#58-season-1b-switch-v200), step 7). The previous release has no pending state, so skipping this would show answers as right or wrong at once and never grant their XP and LP.
